# كولومبيا | بوابة المنظمة

بوابة إدارية متكاملة لمنظمات عالم **GTA Roleplay**، بواجهة عربية (RTL) بتصميم زجاجي غامر مع خلفية ثلاثية الأبعاد، ومزامنة مباشرة عبر Socket.io، وتسجيل دخول عبر Discord، ومزامنة تلقائية للرتب.

---

## المزايا

- **تسجيل الدخول عبر Discord** مع التحقق من عضوية الخادم والأدوار والصلاحيات.
- **مزامنة الرتب والصلاحيات** تلقائياً في الخلفية، مع إنهاء فوري لجلسة العضو عند سحب رتبته أو حظره.
- **لوحة قيادة حيّة**: إحصائيات، الهدف الأسبوعي، الإعلانات، آخر العمليات، وحالة الدوام.
- **المتجر**: تصفح المنتجات، سلة مشتريات، معاينة ثلاثية الأبعاد، وإرسال الطلبات.
- **الطلبات**: متابعة الطلبات وتحديث حالتها لحظياً.
- **الدوام والحضور**: بدء/إنهاء الدوام، قفل الدوام الليلي، وسجل الدوام والتقارير.
- **غرفة العمليات**: تسجيل العمليات والنتائج والمشاركين مع احتساب الهدف الأسبوعي (انتصار يضيف، خسارة تطرح بحد أدنى صفر).
- **المزرعة**: بقع زراعية بمحاصيل وأوقات نمو، حصاد يرفع المخزون تلقائياً للـمتجر.
- **الخزينة**: دفتر حسابات الدخل والمصروف مع مخططات وملخص مالي.
- **المتجر الداخلي**: شراء العناصر من رصيد العضو.
- **سجل الانضباط**: ملاحظات، تحذيرات، وغرامات تُخصم آلياً من رصيد العضو.
- **التذاكر**: طلبات الإجازة والترقية والشكاوى مع مسار موافقة.
- **لوحة الشرف**: ترتيب أفضل المساهمين.
- **لوحة الإدارة**: إدارة المنتجات، الأعضاء، الأرصدة، الرتب، الحظر، الإعلانات، الهدف، الإعدادات، وسجل التدقيق.
- **تخصيص كامل** لاسم المنظمة ونصوص الواجهة من ملف واحد.
- **تحديث مباشر** للواجهة عند نشر إصدار جديد (بدون تحديث يدوي).

---

## التقنيات

- **الخادم:** Node.js، Express، Mongoose (MongoDB)، Socket.io، discord.js
- **الجلسات:** express-session + connect-mongo
- **الواجهة:** JavaScript حديث (ES Modules)، HTML/CSS، بدون خطوة بناء (No build step)
- **المؤثرات:** three.js (خلفية ومعاينة 3D)، Chart.js (المخططات)
- **الأمان:** Helmet (CSP)، express-rate-limit، express-mongo-sanitize، Multer + Cloudinary للصور

---

## المتطلبات

- Node.js الإصدار 18 أو أحدث.
- قاعدة بيانات MongoDB (محلية أو Atlas).
- تطبيق Discord (OAuth + Bot) — مطلوب لتسجيل الدخول ومزامنة الرتب.
- حساب Cloudinary (اختياري) — لرفع صور المنتجات.

## التثبيت السريع

```bash
# 1) تثبيت الاعتماديات
npm install

# 2) تجهيز ملف البيئة
copy .env.example .env      # ويندوز
# cp .env.example .env      # لينكس/ماك
# ثم املأ القيم داخل .env

# 3) تهيئة البيانات الأولية (اختياري لكن مُنصح به)
npm run seed

# 4) التشغيل
npm start
```

ثم افتح المتصفح على: `http://localhost:3000`

## متغيرات البيئة (.env)

| المتغير | الوصف |
| --- | --- |
| `NODE_ENV` | `production` أو `development`. |
| `PORT` | منفذ الخادم (افتراضي 3000). |
| `BASE_URL` | الرابط العام الكامل للموقع (بدون `/` في النهاية)، يُستخدم لردّ OAuth. |
| `SESSION_SECRET` | نص عشوائي طويل لتشفير الجلسات. ولّده بـ `openssl rand -hex 32`. |
| `MONGODB_URI` | رابط اتصال MongoDB. |
| `DISCORD_CLIENT_ID` | معرّف تطبيق Discord. |
| `DISCORD_CLIENT_SECRET` | السر الخاص بتطبيق Discord. |
| `DISCORD_TOKEN` | توكن البوت (لمزامنة الأدوار والطرد الفوري). |
| `DISCORD_GUILD_ID` | معرّف خادم Discord. |
| `ROLE_ADMIN_ID` | معرّف رتبة المدير العام. |
| `ROLE_OPS_ID` | معرّف رتبة الضابط. |
| `ROLE_MEMBER_ID` | معرّف رتبة العضو. |
| `ROLE_SHOP_ID` | معرّف رتبة المتجر. |
| `CLOUDINARY_CLOUD_NAME` | اسم حساب Cloudinary. |
| `CLOUDINARY_API_KEY` | مفتاح Cloudinary. |
| `CLOUDINARY_API_SECRET` | سر Cloudinary. |
| `BUILD_ID` | (اختياري) معرّف الإصدار لإعادة تحميل التبويبات؛ يُولّد تلقائياً إن تُرك فارغاً. |
| `LOG_LEVEL` | مستوى التسجيل (افتراضي `info`). |

> إذا تركت إعدادات Discord أو Cloudinary فارغة، يعمل الخادم مع تسجيل تحذيرات وتبقى الخدمات المرتبطة بها معطّلة.

## إعداد Discord

1. أنشئ تطبيقاً من [Discord Developer Portal](https://discord.com/developers/applications).
2. من قسم **OAuth2**، أضف رابط رد الاتصال: `BASE_URL/api/auth/callback`.
3. انسخ `Client ID` و `Client Secret` إلى ملف `.env`.
4. من قسم **Bot**، أنشئ بوتاً وانسخ التوكن إلى `DISCORD_TOKEN`، وفعّل الخيار **Server Members Intent**.
5. فعّل البوت في خادمك واحصل على معرّفات الرتب (`ROLE_*_ID`) من إعدادات الخادم.
6. احصل على `DISCORD_GUILD_ID` من خادمك (يظهر في رابط الخادم أو من إعدادات المطوّر).

---

## Cloudinary (رفع الصور)

1. أنشئ حساباً على [Cloudinary](https://cloudinary.com).
2. انسخ `Cloud Name` و `API Key` و `API Secret` إلى ملف `.env`.
3. عند إضافة صور المنتجات من لوحة الإدارة يتم رفعها تلقائياً إلى Cloudinary.

## الرتب والصلاحيات

| الرتبة | الترتيب | الصلاحيات |
| --- | --- | --- |
| مدير عام (admin) | 4 | كل الصلاحيات ولوحة الإدارة. |
| ضابط (ops) | 3 | إدارة العمليات، الانضباط، الخزينة، والتذاكر. |
| عضو (member) | 2 | لوحة القيادة، الدوام، المزرعة، المتجر الداخلي... |
| متجر (shop) | 1 | المتجر والطلبات. |
| زائر (guest) | 0 | بدون صلاحيات. |

تُحدَّد رتبة العضو من أدواره في Discord وتُزامَن تلقائياً. وعند خفض الرتبة أو الحظر تُنهى جلسة العضو فوراً.

## تخصيص العلامة والنصوص

كل شيء قابل للتغيير من ملف واحد: **`config/site.js`**

- اسم المنظمة وشعارها النصي والشعار الترويجي.
- اللغة والاتجاه والمنطقة الزمنية والعملة.
- الألوان والثيم.
- عناصر القائمة الجانبية وصلاحياتها.
- كل النصوص العربية للواجهة (الرسائل، الأزرار، الحالات...).

بعد التعديل، تُقرأ القيم تلقائياً ويعرضها الخادم عبر `/api/site` دون الحاجة لتغيير أي كود آخر.

## هيكل المشروع

```
config/
  env.js            # قراءة متغيرات البيئة

  index.js          # تجميع التطبيق وتشغيل الخادم
  db.js             # الاتصال بقاعدة البيانات

  services/         # المنطق (الرتب، الهدف، المزرعة، السوكِت، البوت، الجدولة...)

  middleware/       # المصادقة، الأمان، رفع الملفات، الأخطاء
  sockets/          # تهيئة Socket.io والغرف
  utils/            # أدوات الوقت والحسابات
scripts/
  seed.js           # البيانات الأولية
  check.js          # فحص syntax
public/
  index.html        # قشرة الواجهة
  css/app.css       # نظام التصميم
  js/               # الواجهة (الحالة، الـAPI، السوكِت، المكوّنات، الخلفية 3D)
  js/pages/         # صفحات الواجهة
```

## النشر

مثال على منصة Render:

1. ارفع المشروع إلى مستودع Git.
2. أنشئ خدمة Web جديدة واختر `Node` كبيئة.
3. أمر البناء: `npm install` — أمر التشغيل: `npm start`.
4. أضف متغيرات البيئة من لوحة المنصة (خاصة `BASE_URL` و `MONGODB_URI` و `SESSION_SECRET`).
5. اضبط `BASE_URL` على رابط النشر، وحدّث رابط رد OAuth في Discord ليطابقه.

> تنبيه: تأكد من أن `SESSION_SECRET` طويل وعشوائي في بيئة الإنتاج، وأن الاتصال بـMongoDB آمن.
